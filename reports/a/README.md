# Часть А: данные и обучение на аэроснимках

Реализован вариант для RGB-съёмки с дрона. Исходный датасет UAVVaste содержит один класс `rubbish`. Эта работа демонстрирует обнаружение видимого мусора. Она не устанавливает качество на море, не распознаёт материалы мусора, нефтяное или химическое загрязнение и не обучает спутниковую модель.

Код участника А находится в `src/data/`, `src/training/`, `configs/a/`, `notebooks/a/`, `reports/a/`. Друг может независимо создавать `src/evaluation/`, `src/inference/`, `app/`, `configs/b/`, `notebooks/b/`, `reports/b/`. Зависимости меняет А; общий README в конце собирает Б.

## Установка в Windows / PowerShell

Все команды выполняются из корня репозитория. Проверяемое окружение — Python 3.13. На машине с NVIDIA установите CUDA-сборку PyTorch; на машине без NVIDIA используйте CPU-вариант. Системный CUDA Toolkit для готовых wheels не требуется.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

CPU-вариант: в команде установки PyTorch замените `cu124` на `cpu`. Выбор пары torch/torchvision следует [официальной таблице PyTorch](https://pytorch.org/get-started/previous-versions/#v260). Для обучения на CPU можно передать `--device cpu`; на NVIDIA — `--device 0`. По умолчанию выбирается доступный GPU, иначе CPU. Зафиксированные версии фактически установленного окружения сохраняются отдельно в `requirements-lock.txt` после проверки.

## Данные и EDA

```powershell
.\.venv\Scripts\python.exe -m src.data.download
.\.venv\Scripts\python.exe -m src.data.audit
```

По умолчанию загружается официальный архив Zenodo с проверкой опубликованного MD5. Уже проверенные изображения используются повторно. Источники и SHA-256 разметки записываются в `data/raw/uavvaste/download_manifest.json`. Полный исходный набор занимает около 3 ГБ, архив также сохраняется локально. Для небольшой пробной выборки можно указать `--source images --limit 48 --output data/raw/uavvaste_sample --workers 2`; использовать затем `annotations_subset.json` и соответствующие пути. Если сервер изображений отвечает 429, загрузчик прекращает новые сетевые запросы; используйте архив. Ошибки перечислены в манифесте, повторный запуск использует ранее проверенные файлы.

EDA создаёт `reports/a/audit/summary.json`, таблицы классов/изображений/рамок, `distributions.png`, `annotated_examples.jpg` и контактные листы по сериям. Ноутбук `notebooks/a/01_dataset_audit.ipynb` объясняет эти шаги и позволяет повторить их. В редакторе выберите интерпретатор `.venv/Scripts/python.exe`.

Источник: [UAVVaste](https://github.com/PUTvision/UAVVaste), [статья авторов](https://doi.org/10.3390/rs13050965), [архив данных](https://doi.org/10.5281/zenodo.8214061). Не переносите изображения и веса в обычные Git-коммиты. Используйте ссылки на исходные данные и отдельное хранилище для весов; условия использования проверяйте по первоисточнику, лицензия репозитория кода сама по себе не заменяет лицензию изображений.

В исходной разметке каждый из 772 кадров содержит хотя бы один объект. Отдельных чистых сцен без мусора нет. Для проверки ложных срабатываний на чистом побережье нужен дополнительный размеченный набор отрицательных примеров. Медиана короткой стороны объекта после resize к 640 — около 10 пикселей; у 1275 из 3718 рамок она меньше 8 пикселей. Поэтому качество на мелком мусоре и эффект нарезки нужно исследовать отдельно.

## Фиксированное разбиение

Загрузчик создаёт `groups_suggested.csv` по префиксам серий в именах кадров. **Это эвристика, а не подтверждённые идентификаторы полётов или мест.** Она держит известные серии вместе, но не гарантирует отсутствие пересечения территорий между сериями. Для окончательной оценки просмотрите контактные листы, объедините серии одной сцены и сохраните проверенный CSV `image_id,group_id`. Для своих съёмок используйте реальные полёты/локации.

Первое воспроизводимое разбиение по предложенным сериям:

```powershell
.\.venv\Scripts\python.exe -m src.data.prepare --annotations data/raw/uavvaste/annotations.json --images data/raw/uavvaste/images --groups data/raw/uavvaste/groups_suggested.csv --exif-policy raw-pixels --first-frame --output data/processed/uavvaste
```

Подготовка проверяет ссылки COCO, размеры, EXIF orientation, числовые координаты и площади рамок. В UAVVaste встречаются EXIF-повороты, при этом размеры COCO и визуально проверенные рамки соответствуют исходным пикселям. Режим `--exif-policy raw-pixels` сохраняет исходную ориентацию пикселей и удаляет EXIF-поворот при экспорте. Для нового источника сначала проверьте систему координат: по умолчанию такие изображения отклоняются. Рамки, частично выходящие за границы, обрезаются; недопустимые аннотации вызывают явную ошибку. Точные дубликаты декодированных изображений удаляются; связанные ими группы объединяются до split. Если разметка дубликатов противоречит друг другу, требуется исправление источника. Наборы стремятся к 70/20/10, но серии неделимы, поэтому фактические доли могут отличаться.

В результате: `images/{train,val,test}`, `labels/{train,val,test}`, `data.yaml`, `dataset_manifest.json`, `split_manifest.csv`, `tiles.csv`. Классы перенумеровываются от нуля; текущий класс `0 = rubbish`. Разметка YOLO: `class_id x_center y_center width height`, координаты нормированы 0–1.

Некоторые JPEG этого источника содержат несколько кадров. `--first-frame` явно выбирает первый кадр, которому соответствует разметка. Кадры с EXIF, несколькими изображениями или некорректным завершающим маркером JPEG экспортируются в PNG без метаданных, чтобы обучающая библиотека не меняла подготовленные изображения автоматически.

Папка результата должна быть новой или пустой. При изменении данных создавайте новую версию папки. Не исправляйте разметку и split между сравниваемыми экспериментами.

Если нет групп, конвертер требует явное `--allow-image-split` и помечает результат как предварительный с риском утечки. Это не протокол финальной оценки.

## Большие снимки и маленькие объекты

Чтобы создавать фрагменты, добавьте `--tile-size 1024 --overlap 0.2` и укажите новый `--output data/processed/uavvaste_tiles`. Разбиение выполняется **до** нарезки. Сохраняются все положительные пересечения рамок с фрагментом, включая частично обрезанные объекты; пустые фрагменты сохраняются как отрицательные примеры. Это явная политика, которую можно исследовать отдельно, поскольку очень маленькие обрезанные объекты усложняют обучение.

`tiles.csv` связывает фрагмент с исходным кадром и смещением. Друг сможет переносить предсказанные рамки в координаты исходного кадра и удалять дубли перекрывающихся фрагментов. Обработка видео, уникальный подсчёт объектов между кадрами и географические координаты — отдельные задачи; суммирование всех покадровых обнаружений не является числом уникальных предметов.

## Обучение

Сначала короткий прогон для проверки загрузки, GPU, loss, validation и сохранения весов:

```powershell
.\.venv\Scripts\python.exe -m src.training.train --config configs/a/smoke.yaml --dry-run
.\.venv\Scripts\python.exe -m src.training.train --config configs/a/smoke.yaml
```

Основные сравнимые эксперименты:

```powershell
.\.venv\Scripts\python.exe -m src.training.train --config configs/a/yolov8n_baseline.yaml
.\.venv\Scripts\python.exe -m src.training.train --config configs/a/yolov8n_aug.yaml
```

Для последовательного запуска обоих экспериментов с бюджетом 20 эпох и автоматического отчёта:

```powershell
.\scripts\run_a_experiments.ps1 -Epochs 20 -Batch 4 -Device 0 -Suffix 20
```

E1 дообучает предварительно обученную YOLOv8n. E2 меняет политику аугментации; данные, seed, optimizer, epochs и разрешение совпадают. Готовая COCO-модель до дообучения не является корректным полноклассовым baseline для `rubbish`.

Параметры можно переопределить через `--epochs`, `--batch`, `--imgsz`, `--device`, `--fraction`, `--data`, `--name`. Для сравнения изменяйте бюджет обучения одинаково у обоих запусков. Переопределения сохраняются в `effective_config.yaml`. Повторный запуск требует нового имени, например `--name a_n_baseline_v2`; старые результаты не перезаписываются. GPU с 4 ГБ памяти может потребовать меньший batch. Уменьшение `imgsz` влияет на мелкие объекты.

В конфигурациях отключён AMP: установленная Ultralytics предупреждает о возможных NaN для GTX 1650 и сама отключает смешанную точность. Это сохраняет одинаковую точность вычислений у сравниваемых запусков. Фактически использованный режим также записывается в `runtime` внутри конфигурации результата.

Оба основных эксперимента используют `cache: ram`: в оперативной памяти хранятся уменьшенные входные изображения, что ускоряет повторные эпохи. Если памяти мало, задайте `cache: false` в обеих конфигурациях. Ultralytics предупреждает, что RAM-кэш не гарантирует побитовую воспроизводимость; одинаковый seed не заменяет повторных экспериментов.

Модуль использует train и val. Test не передаётся в обучение; окончательную оценку проводит Б после выбора модели и настроек. Метрики, сохраняемые здесь, обозначены как validation, а не test. Smoke-run не характеризует качество модели. Результаты читаются в `notebooks/a/02_training_experiments.ipynb`.

Для завершённых базового и augmented запусков сформируйте таблицу и график:

```powershell
.\.venv\Scripts\python.exe -m src.training.summarize models/a/a_n_baseline models/a/a_n_aug
```

Команда проверяет совпадение манифеста датасета, YAML с путями split, классов, seed, исходных весов, архитектуры и режима обучения, включая фактический AMP. Между запусками нельзя менять содержимое изображений и меток в подготовленном наборе. В `reports/a/experiments` сохраняются настоящие метрики validation; одиночный seed не подтверждает статистическую значимость разницы.

## Что передать другу

После успешного запуска появляется `models/a/<имя>/`:

- `best.pt` — веса, выбранные по validation;
- `classes.json` — имена классов;
- `metadata.json` — конфигурация, метрики, ограничения, версии и контрольные суммы;
- `dataset_manifest.json`, `effective_config.yaml`, `environment.json`, `validation_metrics.json`.

Также передайте фиксированное разбиение, `data.yaml` и при необходимости `tiles.csv`. Пути внутри исходного `data.yaml` относительные; скрипт обучения разрешает их относительно файла YAML. Файл `dataset.resolved.yaml` в `runs/` содержит локальные абсолютные пути и не переносится на чужой компьютер как основной конфиг.

У Б остаются единая оценка моделей, YOLOv8s, ошибки на val/test, скорость inference и Streamlit. Веса используются обычным `ultralytics.YOLO(path_to_best_pt)`. Словарь классов считывается из весов или `classes.json`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

Тесты покрывают правильность координат и нарезки, сохранение отрицательных примеров, разделение связанных кадров и дубликатов, детерминированность split, несовпадение классов, сохранение успешного/неуспешного обучения. Проверка качества модели требует настоящего обучения и независимой оценки.
