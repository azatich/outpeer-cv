Состав классов: **`0 = rubbish`**. Веса обычного детектора Ultralytics YOLOv8n; порядок классов записан и в checkpoint.

Локальный архив `models/a/participant_a_handoff.zip` содержит код части А, ноутбуки, эти папки моделей, точную исходную разметку, таблицу групп и разбиения, результаты и инструкции. Изображения и Python-окружение в архив не входят. Веса и исходные данные исключены из Git; передайте ZIP отдельно от ветки. Контрольная сумма архива находится рядом в `participant_a_handoff.sha256`.

Ветка переносится обычным merge/PR. На этой машине изменения сохранены локально; публикация на GitHub выполняется отдельно. Зависимости интерфейса Б добавляет в свой `requirements-b.txt`: окружение устанавливается из обоих списков. Общие файлы проверяются при окончательном объединении.

## Восстановление датасета

1. Установите окружение по [инструкции](README.md).
2. Распакуйте архив в корень клонированного репозитория. Для предотвращения случайной перезаписи используйте новый checkout или предварительно сравните уже существующие файлы.
3. Загрузите изображения командой `.\.venv\Scripts\python.exe -m src.data.download`. Разметка из архива уже зафиксирована и будет использована загрузчиком.
4. Подготовьте изображения и метки. Папка результата должна отсутствовать или быть пустой; архив содержит только эталонные манифесты в `reports/a/dataset/`:

```powershell
.\.venv\Scripts\python.exe -m src.data.prepare --annotations data/raw/uavvaste/annotations.json --images data/raw/uavvaste/images --groups data/raw/uavvaste/groups_suggested.csv --exif-policy raw-pixels --first-frame --output data/processed/uavvaste
```

Сравните строки `data/processed/uavvaste/split_manifest.csv` и переданного `reports/a/dataset/split_manifest.csv`. Совпадение проверяет распределение исходных кадров, группы и хэши декодированных пикселей. Абсолютные пути в JSON-манифесте являются сведениями о машине подготовки; для inference они не нужны. Для оценки используйте `data/processed/uavvaste/data.yaml` с настоящими изображениями. Копия YAML в `reports/a/dataset/` служит записью эксперимента.

Зафиксированное разбиение: train — **522 изображения / 2810 объектов**, validation — **160 / 583**, test — **90 / 325**. Серии определены по именам файлов; разделение по реальным полётам и географическим местам не подтверждено. Не перестраивайте split отдельно для каждой модели.

## Использование весов

```python
from ultralytics import YOLO

model = YOLO("models/a/a_n_baseline_20/best.pt")
print(model.names)  # {0: 'rubbish'}
results = model.predict("path/to/image.jpg", imgsz=640, conf=0.25)
boxes = results[0].boxes.xyxy.cpu().numpy()  # пиксели исходного кадра
scores = results[0].boxes.conf.cpu().numpy()
classes = results[0].boxes.cls.cpu().numpy().astype(int)
```

`0.25` здесь — пример порога для показа рамок, а не найденный оптимальный порог. Выбирайте рабочий порог на validation под задачу и фиксируйте его до финальной проверки. На CPU укажите `device="cpu"` в `predict`.

Участник А использовал только train и validation для обучения и выбора checkpoint. Б проводит единообразную оценку моделей, исследует ошибки и скорость, подключает модель к приложению. Test оценивается после выбора настроек; его нельзя использовать для настройки порога или аугментаций.

## Границы текущего результата

UAVVaste содержит общий видимый мусор на аэроснимках и обычных фотографиях. Оценка на нём не подтверждает качество над морем, на побережье или на спутниковых снимках. Материалы мусора не классифицируются. Чистых сцен без размеченного мусора нет; для проверки ложных срабатываний на чистом побережье нужны дополнительные данные.

Уникальный подсчёт мусора по видео требует сопоставления объектов между кадрами. Площадь загрязнения в квадратных метрах требует масштаба/геопривязки и подходящей разметки; сумма площадей рамок не является площадью загрязнения. Эти величины не следует показывать в интерфейсе как уже измеренные.

Числа экспериментов и их интерпретация находятся в [RESULTS.md](RESULTS.md); [DEFENSE.md](DEFENSE.md) помогает объяснить свою часть на защите.
