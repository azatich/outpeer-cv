# Бутылка, пакет и банка

Модель YOLOv8n находит предметы и определяет их тип. Весь путь: официальная разметка TACO → подготовка изображений и рамок → обучение → выбор порога на validation → итоговый test → Streamlit.

## Запуск готовой модели

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app/main.py
```

Выберите **«Типы мусора · бутылка / пакет / банка»**, загрузите фото и нажмите **«Запустить анализ»**. На фото появятся рамки с типом предмета и уверенностью. Интерфейс также показывает количество бутылок, пакетов и банок; доступны PNG, JSON и CSV.

Веса: `models/b/taco_n_types_30/best.pt`. Порог читается из проверенного `validation/selection.json`. Для переноса готового результата распакуйте `models/b/taco_n_types_30_handoff.zip` в корень другого checkout этого проекта. Архив передаётся отдельно от Git; рядом находится SHA-256. Для приложения полный датасет не нужен.

Примеры для загрузки лежат в `demo/`: `bottle-input.png`, `bag-input.png`, `can-input.png`. Рядом находятся обработанные фотографии и JSON. Метрики и примеры собраны в [RESULTS.md](RESULTS.md).

## Данные и классы

[TACO](https://github.com/pedropro/TACO) содержит настоящие человеческие метки типов предметов. Используется проверенный `annotations.json`, commit `29de1a9ba05a647b83a90f18d7772e20bb23d846`; контрольная сумма фиксируется загрузчиком.

| Наш класс | Исходные категории TACO |
|---|---|
| `bottle` | Other plastic bottle, Clear plastic bottle, Glass bottle |
| `bag` | Paper bag, Plastified paper bag, Garbage bag, Single-use carrier bag, Polypropylene bag |
| `can` | Food Can, Aerosol, Drink can |

Крышки, плёнка и обёртки не получают выдуманный класс «пакет». Прочие категории не являются целевыми. Добавлены 150 фотографий без этих трёх типов: на них может быть другой мусор, поэтому они не называются чистыми.

Всего 680 фото и 834 целевых предмета: 439 бутылок, 122 пакета, 273 банки. Split: 450 train / 181 val / 49 test. Все классы присутствуют в каждой части. Исходные batch-группы сохраняются целиком; независимость мест/авторов не подтверждена. Подробности: [dataset/SUMMARY.json](dataset/SUMMARY.json).

Ориентация EXIF применяется по правилам официального загрузчика TACO. Изображения нормализованы в RGB PNG с длинной стороной до 640 пикселей. Рамки и полигоны масштабируются вместе с изображениями. Исходные фото и разметка остаются в `data/raw/taco/`; результат подготовки — `data/processed/taco_types/`.

## Где находится код

- `src/data/taco.py` — скачивание, объединение настоящих категорий, нормализация и подготовка.
- `configs/multiclass/yolov8n_taco.yaml` — 30 эпох, imgsz=640, batch=4, seed=42.
- `src/training/train.py` — общее обучение Ultralytics; `--participant b` выбирает папки результатов.
- `src/evaluation/` — оценка с учётом класса, выбор порога только на val, фиксированная проверка test.
- `src/inference/predict.py` — загрузка обученных весов, рамки, типы и количество по классам.
- `app/main.py` — приложение; сохраняет поддержку старых однотипных моделей UAVVaste.

## Повторное обучение

Для **дообучения из наших обученных весов** используйте [эксперимент finetune](finetune/README.md) и `scripts/run_types_finetune.ps1`. Он запускается из `models/b/taco_n_types_30/best.pt` с меньшим lr0 и сравнивает старый и новый варианты на одинаковом validation. Новые морские данные этим не добавляются.

На этой машине подготовленный датасет уже есть. Новый запуск сохраняет отдельные веса и отчёты:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_types_experiment.ps1 -SkipData -Device 0 -Name taco_n_types_v2 -Reports reports/multiclass/rerun_v2
```

Скрипт обучает, выбирает порог на validation, проверяет замороженный выбор на test и создаёт отчёт с архивом. Старые результаты не перезаписываются. Приложение находит проверенные `selection.json` внутри `reports/multiclass/`, включая отдельные повторные запуски.

Для первой подготовки на машине без данных используйте отдельную новую папку reference:

```powershell
.\.venv\Scripts\python.exe -m src.data.taco --reference reports/multiclass/fresh_dataset
```

Затем укажите эту папку в поле `reference` конфигурации оценки. Для точного повторения сохранённых метрик нужны те же подготовленные пиксели и метки: исходные сетевые фотографии могут меняться; evaluation проверяет хэши относительно reference.

Качество на дроновых, морских и спутниковых снимках отдельно не измерено. Числа этого эксперимента относятся к TACO и не сравниваются напрямую с метриками UAVVaste.
